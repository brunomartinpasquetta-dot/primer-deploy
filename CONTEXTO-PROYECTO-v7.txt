CONTEXTO DEL NEGOCIO
---------------------
Sistema ERP generico para gestion de cosecha agricola.
Nombre: CosechaApp — Gestion de Cultivos

Aplica a: frutilla, soja, trigo, arandanos, vid, zapallitos, cualquier cultivo
Usuarios: productores, encargados de campo, operarios
Dispositivos: celular en campo + PC en oficina/galpon

REGLAS DE CAMPANA
------------------
- Solo UNA campana activa a la vez
- Al activar una campana se desactiva la actual automaticamente
- TODOS los modulos precargan la temporada activa automaticamente en sus selectores
- Patron: fetch('/api/temporadas/activa') -> setear select -> disparar evento change

LOGICA DE NEGOCIO — REGLAS INAMOVIBLES
----------------------------------------
1. VENTA -> INGRESO en Caja + EGRESO en MovimientosDeposito + EGRESO en StockMercaderia
2. DESCARTE -> EGRESO en MovimientosDeposito (tipo='egreso_descarte') — NO mueve Caja
3. COMPRA efectivo -> EGRESO automatico en Caja dentro de la misma transaccion
4. COMPRA CC -> debito en CuentaCorrienteProveedores
5. INGRESO deposito -> INSERT MovimientosDeposito + UPDATE StockMercaderia
6. JUNTADA -> destino obligatorio: 'deposito', 'descarte', 'venta_directa' o 'mixto'
   - Suma de kilos asignados debe == kilos cosechados (tolerancia +-0.01)
   - Cosechero obligatorio antes de registrar
   - Permite destino mixto: parte deposito + parte descarte en una sola transaccion
7. ANULACION -> NUNCA eliminar registros. Soft-delete con estado='anulada'.
   Reversion completa: stock, caja, cuenta corriente en una transaccion.
   Registrar motivo + audit trail completo.

BALANCE: cosechado = en deposito + vendido + descartado

SISTEMA DE AUDITORIA (implementado 02/04/2026)
-------------------------------------------------
Tablas: AuditoriaCompras, AuditoriaVentas
Campos: (movimiento_id, accion, campo, valor_anterior, valor_nuevo, usuario_id, usuario_nombre, fecha_hora)

Compras: PATCH con auditoria campo-por-campo, POST /:id/anular (revierte stock+caja+CC)
Ventas: via stock-mercaderia.js — PATCH /historial/:id/auditado, POST /historial/:id/anular

Columna 'estado' NVARCHAR(20) DEFAULT 'confirmada' en: Compras, StockMercaderia, MovimientosDeposito
Filas anuladas: opacity:0.5, line-through, badge roja "Anulada"
Frontend: boton "Auditoria" en barra filtros, modal con tabla + filtros tipo/busqueda

AUTO-REMITO (implementado 02/04/2026)
--------------------------------------
Patron: NO-REM001, NO-REM002, NO-REM003...
Si el usuario no completa remito, se genera automaticamente.
Busca ultimo NO-REM% + 1 con padStart(3, '0').
Ventas: remitos gestionados via tabla Remitos + RemitoItems.

FLUJOS DE MERCADERIA
---------------------
- Flujo A — Fresco directo: juntada -> deposito (requiere_despalillado=0) -> StockMercaderia inmediato
- Flujo B — Camara fria: juntada -> stock_pendiente=1 -> despalillado -> StockMercaderia
- Flujo C — Fresco despalillado: deposito con requiere_despalillado=1

EMBALAJE EN VENTAS
-------------------
Tabla VentaEmbalaje (movimiento_id FK, producto_id FK, cantidad, costo_unitario, costo_total, retornable, cantidad_devuelta)
Retornables: descuentan stock al salir, se reponen con POST /api/depositos/devolucion-embalaje
KPI "Cajones en circulacion" visible cuando hay retornables pendientes

FILTROS UNIFICADOS — PATRON OBLIGATORIO
-----------------------------------------
Todos los modulos con grilla usan .filtros-barra con input unico + datalist.
Helpers utils.js: poblarDatalist(), matchFiltro()
Filtrado SIEMPRE client-side sobre array en memoria.
Solo select de temporada si dispara re-fetch.
